# HealthVault portable export format

Current export schema: `1`.

An export named `healthvault_export_<timestamp>.healthvault-export.zip` is deliberately independent of FastAPI, React, SQLAlchemy, Ollama, and SQLite internals.

```text
manifest.json
checksums.sha256
DATA_FORMAT.md
profiles/{profiles.json,profiles.csv,profiles.md}
providers/...
visits/...
documents/...
prescriptions/...
medications/...
prescribed_medications/...
appointments/...
notes/...
observations/...
reminders/...
dose_events/...
voice_notes/...
extractions/...
tags/...
entity_tags/...
audit_logs/...
attachments/documents/originals/...
attachments/voice/originals/...
```

## Encoding and primitive types

- Text: UTF-8 JSON/Markdown and UTF-8 with BOM CSV for spreadsheet compatibility
- IDs/relationships: stable UUID strings
- Unknown: JSON `null`, never a guessed sentinel
- Dates: ISO `YYYY-MM-DD`
- Timestamps: ISO 8601 with timezone offset where known
- Booleans/numbers: native JSON primitives
- Flexible schedules/recurrences/extractions: JSON encoded in their canonical database field

`manifest.json` includes format name, export/database/application versions, timestamp, entity counts, and unknown-field policy. `checksums.sha256` covers the manifest, schema document, every entity representation, and each original attachment.

## Import compatibility

Import first performs a dry-run inspection. Newer unsupported schema versions are refused. Stable UUIDs are merged without inventing replacements. Unknown fields are not silently discarded: they are reported and, during an actual import, written to a timestamped report under the local logs directory. Original attachments are copied by their canonical paths.

Before a non-dry-run import into a valuable vault, create and test an encrypted backup.

## Building another importer

Use the JSON representation as authoritative. CSV and Markdown are convenience views. Recreate relationships by UUID, preserve original paths and SHA-256, retain audit records, and treat `verification_status` as medical-safety provenance rather than a display-only field.
